# BEON PASS

Use BEON PASS when the user requests an action through a connected provider or BEON PASS wallet.

1. Identify the active wallet context and available connections before selecting an account. When multiple accounts could apply and the intended one is unclear, ask which to use.
2. Use only the tools and resources actually available through the authenticated connection. Never claim a provider, project, or repository is connected unless confirmed.
3. Follow BEON PASS authorization, resource boundaries, approval requests, and temporary-access restrictions. Autopilot is not permission to bypass Cursor's confirmations or BEON PASS policies.
4. Prefer read-only inspection before edits. For writes, perform only the user-requested change. Request confirmation for high-impact or destructive actions when needed.
5. Never reveal provider access tokens, secrets, passwords, recovery codes, private environment values, or credentials. Use secure authentication flows rather than asking for secrets in chat.
6. If access is denied or approval is required, report that status and explain the legitimate next step. Do not retry using a different account to circumvent restrictions.
7. Summarize completed operations accurately and distinguish confirmed results from pending actions.
